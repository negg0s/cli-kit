# cli-kit Implementation Plan

> **For agentic workers:** Implement the tasks in order. Each behavior starts with a failing test.

**Goal:** Build a small TypeScript toolkit for authoring typed, dependency-free command-line apps, including argument parsing, help, completion, a test harness, and a starter generator.

**Architecture:** `src` contains public typed command definitions, parser, runner, completion generation, and scaffold logic. The runtime has no dependencies and uses Node.js built-ins. The package ships compiled ESM and declarations, plus a `create-cli-kit` binary.

**Tech Stack:** TypeScript, Node.js 22+, Node test runner, npm.

**Spec:** This plan is the product brief. The user approved the selected CLI toolkit and delegated feature choices.

## Global Constraints

- Work only under `D:\Projects\cli-kit` and keep npm cache and temporary files on D:.
- Runtime dependencies: none.
- No AI features, telemetry, auto-update, exaggerated market claims, or long dash punctuation in project copy.
- Help, parser errors, and command results must be deterministic and testable without process.exit.
- User requested pushing the finished project to GitHub.

## Review Focus

- Malformed values and unknown options must return actionable errors without throwing.
- Help and completion must handle commands and options with spaces or punctuation safely.
- Scaffold paths must reject traversal and avoid overwriting existing user files.
- Generated app must install/build and run on supported Node versions.
- Runtime package entry points and declarations must match emitted files.

### Task 1: Typed command definitions and parser

**Files:** `src/types.ts`, `src/parse.ts`, `src/index.ts`, `test/parse.test.mjs`, package config.

**Interfaces:** `defineCommand` accepts a named command with typed options and positional argument definitions. `parseArgs` consumes an option definition map and argv, returning values and positionals or a structured parse error. Option keys infer handler value types.

- [x] Add tests for string, boolean, number, enum, aliases, defaults, positional values, and invalid/unknown input.
- [x] Run tests and confirm the missing API fails for the expected reason.
- [x] Implement the smallest parser and definitions to pass.
- [x] Run tests and typecheck.

### Task 2: Runner, help, and in-process test harness

**Files:** `src/run.ts`, `src/help.ts`, `src/testing.ts`, tests.

**Interfaces:** `runCli({name, version, commands}, argv)` returns `{exitCode, stdout, stderr}`. Handlers write through captured `stdout` and `stderr`, receive typed options and arguments, and may return a numeric exit code. Help supports overview, command, and versioned JSON output. This first version has a flat command list, no nested commands.

- [x] Add failing tests for dispatch, async handlers, help, errors, and captured output.
- [x] Confirm red, implement, then run the full suite and typecheck.

### Task 3: Completion, generator, documentation, and release readiness

**Files:** `src/completion.ts`, `src/create.ts`, `src/bin/*`, `test/completion.test.mjs`, `test/create.test.mjs`, `README.md`, `LICENSE`, `.gitignore`, GitHub Actions workflow.

**Interfaces:** Generate static bash, zsh, and fish completion scripts from command metadata. `createCliProject({name, directory})` validates the package name, creates a minimal starter only at a nonexistent target, rejects traversal, and is exposed through `create-cli-kit`.

- [x] Implement generation and test the generated project's build and help output.
